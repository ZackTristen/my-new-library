# Диаграмма компонентов веб-приложения "Моя библиотека"

Этот документ описывает основные компоненты архитектуры приложения, сгруппированные по шаблону **MVC (Model-View-Controller)**.

---

## 1. Model (Модель: Данные и бизнес-логика)

Компоненты этого слоя отвечают за структуру данных, их хранение и взаимодействие с базой данных.

*   **`models.py`**
    *   **Назначение:** Определяет структуру базы данных с помощью ORM-моделей SQLAlchemy.
    *   **Ключевые классы:**
        *   `User`: Описывает таблицу пользователей (id, username, password).
        *   `Book`: Описывает таблицу книг (id, title, author, year, cover_image).
        *   `UserBook`: Таблица связи для реализации отношения "многие-ко-многим" между пользователями и книгами, формируя личные каталоги.
    *   **Соотношение:** Является "чертежом" для базы данных. Используется Контроллером для выполнения CRUD-операций (Create, Read, Update, Delete).

*   **`database.py`**
    *   **Назначение:** Инициализация подключения к базе данных и регистрация кастомных команд Flask.
    *   **Ключевые элементы:**
        *   `db = SQLAlchemy()`: Экземпляр SQLAlchemy, через который идут все взаимодействия с БД.
        *   `init_db_command()`: Функция, регистрирующая команду `flask init-db` для создания таблиц в базе данных.
    *   **Соотношение:** Предоставляет объект `db` для `app.py` и `models.py`, связывая приложение с ORM.

*   **`instance/my_library.db`**
    *   **Назначение:** Файл базы данных SQLite.
    *   **Соотношение:** Физическое хранилище всех данных. Модифицируется только через слой Модели (SQLAlchemy).

---

## 2. View (Представление: Пользовательский интерфейс)

Компоненты этого слоя отвечают за то, как данные и элементы управления отображаются для конечного пользователя.

*   **`templates/` (папка)**
    *   **Назначение:** Содержит все HTML-шаблоны, написанные с использованием синтаксиса Jinja2.
    *   **Ключевые файлы:**
        *   `layout.html`: Базовый шаблон, определяющий общую структуру (шапка, меню, подвал). Другие шаблоны наследуют его.
        *   `index.html`, `my_catalog.html`: Отображают списки книг.
        *   `login.html`, `register.html`: Формы для аутентификации.
        *   `admin.html`: Панель администратора.
    *   **Соотношение:** Получает данные от Контроллера и генерирует на их основе финальную HTML-страницу для браузера.

*   **`static/` (папка)**
    *   **Назначение:** Содержит статические файлы, которые отправляются клиенту без изменений.
    *   **Ключевые файлы:**
        *   `css/style.css`: Основной файл стилей. Содержит всю логику верстки, оформления и адаптивности (включая Media Queries).
        *   `js/script.js`: Клиентский JavaScript для интерактивных элементов, таких как "бургер-меню".
        *   `images/`: Папка для изображений (например, обложек книг).
    *   **Соотношение:** Браузер загружает эти файлы по ссылкам из HTML-шаблонов для стилизации и добавления интерактивности страницам.

---

## 3. Controller (Контроллер: Обработка запросов)

Компоненты этого слоя выступают связующим звеном, принимая запросы от пользователя, взаимодействуя с Моделью и выбирая подходящее Представление.

*   **`app.py`**
    *   **Назначение:** Главный файл приложения. Точка входа.
    *   **Ключевые элементы:**
        *   Создание и конфигурация экземпляра Flask `app`.
        *   Регистрация "чертежей" (Blueprints), например, `auth_bp`.
        *   Определение основных маршрутов (`/`, `/my-catalog`, `/admin` и т.д.) и их логики.
    *   **Соотношение:** "Мозг" приложения. Принимает HTTP-запросы, вызывает нужные функции, обращается к Модели за данными и передает их в Представление с помощью `render_template()`.

*   **`auth.py`**
    *   **Назначение:** Модуль, выделенный для логики аутентификации. Реализован как Flask Blueprint.
    *   **Ключевые элементы:**
        *   Маршруты `/login`, `/register`, `/logout`.
        *   Обработка данных форм, проверка паролей, управление сессиями пользователей через Flask-Login.
    *   **Соотношение:** Инкапсулирует всю логику, связанную с пользователями, и подключается к основному приложению в `app.py`.

*   **`extensions.py`**
    *   **Назна-чение:** Вспомогательный модуль для предотвращения циклических импортов.
    *   **Ключевые элементы:**
        *   Инициализация экземпляров расширений (`db`, `login_manager`).
    *   **Соотношение:** Позволяет разным частям приложения (например, `app.py` и `models.py`) использовать один и тот же экземпляр `db` без создания циклической зависимости.

---

## Общая схема взаимодействия

1.  Пользователь вводит URL в браузере (например, `/my-catalog`).
2.  Запрос поступает в **Контроллер** (`app.py`).
3.  Обработчик маршрута `/my-catalog` вызывает **Модель** (`UserBook.query...`), чтобы получить список книг для текущего пользователя из базы данных (`my_library.db`).
4.  Контроллер передает полученный список книг в **Представление** (`render_template('my_catalog.html', books=...)`).
5.  Шаблон `my_catalog.html` (View) генерирует HTML-страницу, вставляя в нее данные о книгах.
6.  Браузер получает готовый HTML и дополнительно запрашивает статические файлы (`style.css`, `script.js`) для его оформления и интерактивности.
