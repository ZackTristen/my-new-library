# Спецификация диаграммы компонентов UML для проекта "Моя Библиотека"

Эта спецификация описывает основные компоненты системы и их зависимости, чтобы можно было построить соответствующую UML-диаграмму.

## 1. Компоненты

*   **`[Клиент (Веб-браузер)]`**
    *   **Описание:** Пользовательский интерфейс, который отображает HTML, выполняет CSS и JavaScript.
    *   **Артефакты:** HTML-страницы, `style.css`, `script.js`.

*   **`[Веб-приложение (Flask)]`**
    *   **Описание:** Основной серверный компонент, обрабатывающий HTTP-запросы, бизнес-логику и рендеринг шаблонов.
    *   **Артефакты:** `app.py`, `config.py`.
    *   **Предоставляемые интерфейсы:** `HTTP Endpoints` (e.g., `/`, `/book/<id>`, `/admin`).

*   **`[Компонент Аутентификации]`**
    *   **Описание:** Отвечает за регистрацию, вход и выход пользователей. В терминах Flask - это Blueprint.
    *   **Артефакты:** `auth.py`, `login.html`, `register.html`.
    *   **Предоставляемые интерфейсы:** `Маршруты аутентификации` (e.g., `/login`, `/logout`).

*   **`[Компонент ORM (SQLAlchemy)]`**
    *   **Описание:** Слой для объектно-реляционного отображения. Предоставляет API для работы с базой данных через Python-объекты.
    *   **Артефакты:** `models.py`, `extensions.py`, `database.py`.
    *   **Предоставляемые интерфейсы:** `Модели данных` (User, Item, etc.), `Сессия БД` (db.session).

*   **`[База данных (SQLite)]`**
    *   **Описание:** Физическое хранилище данных приложения.
    *   **Артефакты:** `instance/my_library.db`.
    *   **Предоставляемые интерфейсы:** `SQL Interface`.

*   **`[Компонент Шаблонов (Jinja2)]`**
    *   **Описание:** Набор HTML-шаблонов, которые динамически заполняются данными на сервере.
    *   **Артефакты:** Файлы в директории `templates/`.
    *   **Предоставляемые интерфейсы:** `HTML-структура`.

*   **`[Компонент Статических Ресурсов]`**
    *   **Описание:** Хранилище для CSS, JavaScript и изображений, которые передаются клиенту "как есть".
    *   **Артефакты:** Файлы в директории `static/`.
    *   **Предоставляемые интерфейсы:** `Файлы стилей и скриптов`.

## 2. Зависимости и связи (Подробно)

Здесь подробно описано, как компоненты взаимодействуют друг с другом через их интерфейсы.

*   **Связь:** `[Клиент (Веб-браузер)]` → `[Веб-приложение (Flask)]`
    *   **Описание:** Клиент *использует* интерфейс `HTTP Endpoints`, предоставляемый Веб-приложением, отправляя на него запросы (GET, POST).
    *   **Пример:** Браузер запрашивает страницу `/`, отправляя GET-запрос.

*   **Связь:** `[Веб-приложение (Flask)]` → `[Компонент Шаблонов (Jinja2)]`
    *   **Описание:** Веб-приложение *использует* интерфейс `HTML-структура`, предоставляемый Компонентом Шаблонов, для генерации конечной HTML-страницы.
    *   **Пример:** `app.py` вызывает `render_template('index.html', ...)`.

*   **Связь:** `[Веб-приложение (Flask)]` → `[Компонент Аутентификации]`
    *   **Описание:** Веб-приложение *делегирует* обработку запросов `Маршрутам аутентификации` (например, `/login`), которые предоставляет Компонент Аутентификации.
    *   **Пример:** Когда пользователь переходит на `/login`, `app.py` передает управление соответствующей функции из `auth.py`.

*   **Связь:** `[Веб-приложение (Flask)]` → `[Компонент ORM (SQLAlchemy)]`
    *   **Описание:** Веб-приложение *использует* интерфейсы `Модели данных` и `Сессия БД` для запроса, создания, обновления или удаления данных.
    *   **Пример:** `app.py` выполняет `Item.query.all()` для получения списка всех книг.

*   **Связь:** `[Компонент Аутентификации]` → `[Компонент ORM (SQLAlchemy)]`
    *   **Описание:** Компонент Аутентификации *использует* интерфейс `Модели данных` (конкретно `User`) и `Сессию БД` для проверки паролей, поиска пользователей и создания новых записей о пользователях.
    *   **Пример:** `auth.py` выполняет `User.query.filter_by(email=...)` при входе пользователя.

*   **Связь:** `[Компонент ORM (SQLAlchemy)]` → `[База данных (SQLite)]`
    *   **Описание:** Компонент ORM *использует* `SQL Interface`, предоставляемый Базой данных, для выполнения низкоуровневых SQL-запросов. Эта связь является внутренней для SQLAlchemy.
    *   **Пример:** Вызов `db.session.commit()` транслируется в SQL-команды `INSERT` или `UPDATE`, которые отправляются в файл `my_library.db`.

*   **Связь:** `[Компонент Шаблонов (Jinja2)]` → `[Компонент Статических Ресурсов]`
    *   **Описание:** Компонент Шаблонов *ссылается* на интерфейс `Файлы стилей и скриптов`, предоставляемый Компонентом Статических Ресурсов.
    *   **Пример:** В `layout.html` есть тег `<link rel="stylesheet" href="/static/css/style.css">`.

*   **Связь (Обратная):** `[Веб-приложение (Flask)]` → `[Клиент (Веб-браузер)]`
    *   **Описание:** Хотя это не строгая зависимость, можно сказать, что Веб-приложение *генерирует* артефакты (HTML, CSS, JS), которые *используются* Клиентом для рендеринга.
    *   **Пример:** Flask отправляет HTTP-ответ с `Content-Type: text/html`.

## 3. Визуальное представление

Для построения диаграммы:

1.  Создайте прямоугольники для каждого из 7 компонентов, указанных выше, со стереотипом `<<component>>`.
2.  Нарисуйте стрелки зависимостей (пунктирные линии со стрелкой на конце) от зависимого компонента к тому, от которого он зависит (например, от `[Веб-приложение]` к `[Компонент ORM]`).
3.  Используйте "lollipop" и "socket" нотацию для изображения предоставляемых и требуемых интерфейсов, если ваш инструмент это поддерживает. Например, `[Веб-приложение]` предоставляет `HTTP Endpoints`, а `[Клиент]` их требует.
